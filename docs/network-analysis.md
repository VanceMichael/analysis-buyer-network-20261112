# 关系网络分析口径

回答的业务问题：某个采购方被称为“重要桥梁”，是否只是因为它认识的人多（度数高）？
本分析把“桥贡献”与“度数”在方法上分离，并用保持度序列的随机图零模型做对照，
结论可追溯到具体合作记录，导出按配置隐藏单边金额。

## 1. 建图（`src/graph.js`）

- 按 `fromPeriod`/`toPeriod` 时间窗口与可选 `relations` 关系类型过滤原始记录。
- 无向化：`(left,right)` 与 `(right,left)` 视为同一条边，边身份与字段顺序无关。
- 平行边合并策略 `parallelPolicy`：`sum`（默认，金额求和）、`count`（计条数）、
  `max`、`mean`；合并规则与参与合并的全部原始记录 id 一起保存。
- 金额缩放 `scale`：`none`（默认）或 `log1p`，作用于合并后的金额，规则写入图配置。
- 自环始终单列在 `selfLoops`：默认 `report-only`，不进入拓扑与强度；
  `include` 时仅额外计入该节点加权强度，永不进入普通边集合与邻接表，不贡献度。
- 节点 universe（`nodes`）中没有任何边的节点保留为孤立点，各自构成独立连通分量。
- 全程只读原始记录，不修改输入数组或记录对象。

## 2. 社群发现（`src/community.js`）

- 加权 Louvain，模块度分辨率 `resolution`（γ）可调；γ 越高越倾向细分。
- `targetCommunities` 为目标社群数：偏多则按模块度合并增益贪心合并，
  偏少则在最大社群诱导子图上提高分辨率再拆分，拆分越过目标时用受保护合并回收。
  **目标只约束非孤立社群；孤立点社群在合并、拆分两个方向都豁免，绝不被塞进大社群。**
- 图断开时按连通分量分别检测再合并标签，跨分量节点永远不会同群；
  跨分量距离为无穷大，路径类指标在分量内计算，不按零处理。
- 多种子（`seeds`）运行，所有随机顺序来自确定性 RNG（`src/rng.js`）。
- 稳定性用种子间成对调整兰德指数（ARI）矩阵报告，并给全票共识分区。
- 社群标识按成员集合签名稳定命名为 `C01、C02…`，与运行序号无关；
  相同成员集合在任何种子下得到相同名字。

## 3. 桥贡献（`src/bridges.js`）

- 拓扑割边（Tarjan）：删除后会增加连通分量数的边。
- 边介数与节点介数（Brandes，跳数最短路径，按分量分别 BFS）。
- 参与系数：`1 - Σ_c (节点对社群 c 的强度 / 节点总强度)²`，
  纯团内节点为 0，连接越多不同社群越接近 1。
- 每条跨社群边携带 `recordIds`，可逐条追溯到原始合作关系（含期、关系类型、平行边数）。
- 这不是另一种中心性排名：核心是“跨社群”位置，且下一节用零模型排除度数解释。

## 4. 保度零模型（`src/nullmodel.js`）

### 4.1 为什么能排除“只是度数高”

零模型的每张随机图都**逐节点保持原图度序列**：双边交换
`(a,b)+(c,d) → (a,c)+(b,d)`（或 `(a,d)+(b,c)`）只改配对关系，四个端点度都不变。
如果某采购方的桥地位在这些“度数完全相同、仅连线被随机化”的图里普遍出现，
那它就可以被度数解释；如果显著罕见，桥地位才是独立于度数的关系结构贡献。

### 4.2 严格约束与有效性判定

每张实现显式校验，任一不满足即判 `valid=false`，**绝不计入零分布、不产出 p 值**：

1. 度序列逐节点保持（事后独立核算，不只相信交换过程）；
2. 简单图：无自环、无重复边（交换候选遇冲突直接拒绝并重试）；
3. 默认仅同一连通分量内交换，分量大小序列一并保持
   （`allowCrossComponentSwaps=false`）；
4. 成功交换数达到 `minSwaps`（默认 `max(10, 10×边数)`）。

交换尝试达到 `maxAttemptsPerSwap` 仍找不到可行交换时，诊断为
`max-attempts-without-feasible-swap`；边数少于 2 时诊断为 `edges-below-two`。
星形图、三角形等交换空间为空的结构会全部判无效并如实报告，而不是降低标准硬凑。

### 4.3 边权在随机图中如何处置（写入档案）

- `reshuffle`（默认）：拓扑随机化后，把原图边权多重集合用同种子整体随机重洗再挂载。
  边权分布（多重集合）不变，但权重与度的耦合被打断，检验“桥地位是否仅由拓扑造成”。
- `attached`：在带权桩（stub）层面交换，桩权重不动、只改配对。
  逐节点加权强度严格保持（每张实现额外自证，不守恒即判坏实现），
  检验“加权强度也锁定时，纯拓扑结构的贡献”。边携带两端桩权重，
  无向标量权重取均值以保持边权总和守恒。

### 4.4 检验与多重比较

- 对每个节点报告跨社群度、参与系数、节点介数的经验单尾 p 值
  `(1 + 零分布中 ≥ 观测值的个数) / (1 + 有效实现数)`。
- 跨社群度的 p 值再做 Benjamini–Hochberg FDR 调整。
- 有效实现数低于 `minValidRealizations`（默认 max(20, 半数)）时，整个检验标记无效。
- p 值是诚实的：玩具图上若低度桥位在保度随机图中并不罕见，p 值会偏高，不夸大结论。

## 5. 档案、复查与脱敏（`src/analysis.js`）

- 档案 `archiveVersion=1`，保存输入指纹、图口径、社群口径与种子、零模型配置与诊断、
  度序列、分量、自环、社群分区与稳定性、桥贡献、节点检验，以及整体档案指纹。
- `recheck` 用档案内口径重建图并核对指纹、度序列、分量、自环、权重多重集合，
  再用同种子重跑社群发现与零模型，比对分区、稳定性矩阵、跨社群边记录 id 与诊断。
- `hideAmounts=true` 时删除一切可还原单条合作金额的字段（边权、合并金额、节点强度、
  跨群权重、总权重与权重指纹），但保留拓扑与记录 id 的可追溯性。
- 同输入、同配置、同种子的两次运行档案指纹逐位相同，可独立复现。

## 6. 退化情形的已验证行为

| 情形 | 行为 |
| --- | --- |
| 两个稠密团 + 一条桥 | 恢复两团；桥标记为拓扑割边，边介数等于两团节点数乘积 |
| 星形图 | 单社群；零模型无可行交换，全部判无效并给诊断 |
| 全孤立点 | 每点独立社群与独立分量；零模型 `edges-below-two` 判无效 |
| 高度重复边（合并为三角形等小图） | 交换空间为空时如实判无效，不伪造零模型 |
| 度匹配对照（同度的桥位 vs 团内节点） | 介数经验 p 值显著分离，证明贡献独立于度数 |
